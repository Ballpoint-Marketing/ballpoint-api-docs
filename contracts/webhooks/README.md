# Canonical partner webhook contracts

`catalog.json` is the inventory. A catalog entry is either `emitted`, with
versioned logical and wire schemas plus generated fixtures, or `not_emitted`,
which deliberately has no invented schema.

The wire schema is the partner-facing source of truth. The logical schema
describes the payload committed to the outbox; the delivery layer then adds
`event_id`, `event_type`, and `timestamp` before serializing the HTTP body.
Fixtures are generated by `scripts/generate_webhook_contract_fixtures.py`
through the same builders and serializer used by runtime.

For every emitted event, the fixture set separates:

1. logical payload;
2. exact raw wire body and parsed wire body;
3. HTTP headers validated by `headers/contract.json`.

The signature is HMAC-SHA256 over the UTF-8 bytes of
`X-Ballpoint-Timestamp + exact raw body`. Tests recompute it independently
with the synthetic fixture secret. `event_id` is the stable transport dedup
key across retries and endpoints; `X-Ballpoint-Delivery` is unique per HTTP
attempt. For the wrapped RTS event, legacy `id` remains a separate payload
identifier and must not be used in place of `event_id` for transport dedup.

RTS rates are percentages on the inclusive 0–100 scale. The runtime emits at
most 100 `new_rts_pieces` in one event; the golden fixture exercises all 100.
